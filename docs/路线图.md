### 3.2 标签治理

**现在有什么**

- `Library.updateTag` 只能单个改名 / 换组
- 侧栏右键能改名、删除；没有合并，也没有管理面板
- `deleteTag` 会从条目里摘掉引用，但没有"把 B 合并到 A"的能力

**要做什么**

1. `src/main/library.ts` 增加 `mergeTags(fromId, toId)`：把 `entries[].tagIds` 里的 from 全部换成 to、去重，再删除 from；返回受影响记录数
2. `src/main/ipc.ts` 增加 `tag:merge`；`src/preload/index.ts` 与 `index.d.ts` 同步（三处必须一致）
3. 设置页新增「标签管理」：按使用数排序，支持多选、批量重命名、合并、删除
4. 近似重复建议：归一化（去首尾空格、转小写、合并连续空格）+ 编辑距离 ≤ 2 + 包含关系；**只给建议，不自动合并**
5. 侧栏右键补一条「合并到…」，常用路径不用进设置页

**验收**

- 合并后条目引用正确，库里没有孤儿 `tagId`
- 一次操作处理 ≥ 50 个标签不卡顿
- 合并前弹确认，写清影响多少条记录；不做撤销

**成本**：低。工作量主要在管理面板的交互，不在数据层。

**状态**：已完成。`scripts/verify-tags.cjs` 覆盖合并、引用替换、去重、孤儿检查、批量删除与 AI 写入口。

### 3.3 快捷键全覆盖

**现在有什么**

- `Ctrl+F` 定位搜索、`Ctrl+N` 新建、`Delete` 删除、`Esc` 关详情/取消选择、`Ctrl+Enter` 保存
- 卡片上 `Enter` 看详情
- **没有焦点模型**：`selectedIds` 既是"选中"也是"当前项"，`J/K` 这类移动无处落脚

**要做什么**

1. `src/renderer/src/store.ts` 增加 `focusIndex`（与 `selectedIds` 分开）和 `moveFocus` / `toggleFocusSelection` 等动作
2. `src/renderer/src/App.tsx` 承担全局键位；输入框、文本域、`contentEditable` 内一律不触发
3. `Gallery.tsx` 把焦点项滚动进视野（`scrollIntoView({ block: 'nearest' })`）
4. 键位表：

| 键 | 动作 |
| --- | --- |
| `Ctrl+J` / `Ctrl+K` 或 `↑` / `↓` | 上下移动焦点（不改选中） |
| `Space` | 切换当前项选中 |
| `1`–`5` | 给选中的打 N 星 |
| `F` | 收藏 / 取消收藏 |
| `E` | 编辑当前项 |
| `Ctrl+T` | 打开标签面板（批量栏的加标签） |
| `Ctrl+A` | 全选当前筛选结果 |
| `Ctrl+Shift+E` | 导出选中 |
| `?` | 快捷键帮助浮层 |
| `Esc` | 关浮层 / 清空选中（沿用现有行为） |

**验收**

- 不看鼠标完成「筛选 → 全选 → 加标签 → 导出」
- 在搜索框里打 `j` 不会移动卡片；单独按 `j` / `t` 也不触发（字母键统一要求 Ctrl）
- 焦点移动时卡片自动进入视野，不会"选中了但看不见"
- 顶栏与侧栏都有可见的帮助入口，不只知道 `?`

**成本**：低，但焦点模型要想清楚，别做出反直觉行为。

**状态**：已完成。`scripts/verify-keys.cjs` 覆盖 Ctrl+J/Ctrl+K、方向键、Space、Ctrl+A、Ctrl+T、E、1–5、F、?。

### 3.4 AI 辅助打标

**现在有什么**

- 完全没有：`AppConfig` 没有接口配置，`ipc/preload` 没有 AI 通道，界面没有入口
- 好消息：主进程可直接用 Node 自带 `fetch`，**不需要新增依赖**

**要做什么**

1. `src/shared/types.ts` 的 `AppConfig` 增加可选字段：`aiBaseUrl`、`aiApiKey`、`aiModel`、`aiEnabled`
2. 设置页新增「AI 打标（可选）」：三个输入框 + 测试连接按钮；不填 Key 时整个入口隐藏，不影响任何现有流程
3. `src/main/ipc.ts` 增加 `ai:suggestTags(entryIds)`：
   - 取每条记录的首张缩略图转 data URL
   - 连同正向提示词、现有标签列表一起发给 OpenAI 兼容的 `/chat/completions`
   - 要求模型优先从现有标签里选；返回 JSON 候选
4. 候选确认界面：列出「记录 → 候选标签」，默认全选，用户可取消；**确认后才写入**，不做静默写入
5. 失败处理：超时、401、429、返回非 JSON 都翻译成人话，写日志，不阻塞主流程

**验收**

- 20 张图批量打标，用户接受率 ≥ 70%
- 已有标签复用率 ≥ 60%（新造标签 ≤ 8 个）
- 无 API Key 时功能完全消失，所有现有流程不受影响
- 断网 / Key 错 / 超时都有明确提示，不会卡住界面

**两个必须提前定的点**

- **Key 存哪**：只能存 `%APPDATA%\PromptPair\config.json` 明文（禁止原生模块，用不了系统凭据库）。设置页要写明这一点，并支持用环境变量覆盖
- **怎么验收**：接受率需要真实 Key。没有 Key 时先用本地 mock 服务把「请求 → 候选 → 确认 → 写入」链路测通，模型效果单独做一次人工评估

**成本**：中。难度在提示词工程与结果去重，不在代码。

**状态**：已完成。`scripts/verify-ai.cjs` 用本地 mock 跑通「配置 → 带图片请求 → 候选 → UI 确认写入 → 无 Key 降级」；真实模型效果需要用自己的 Key 在 20 张图上验收。

## 五、当前站与下一步：0.7.0 → 0.7.1 → 0.8.0

### 5.1 0.7.0 视频（进行中）

**问题**：现在视频靠系统缩略图抽一帧，能看不能用；时长/分辨率不准，没有播放器。

**目标**

- 库内播放（已有 `<video>` + Range 支持，基本可用）
- 显示真实时长与分辨率 ✅
- hover 预览 3 秒

**方案（已定，2026-10-24）**

- **纯 JS 解析容器头**（`src/main/video-meta.ts`）：mp4/mov/m4v 走 ISOBMFF box、webm/mkv 走 EBML、avi 走 RIFF avih；只读容器头不碰码流，单文件 < 1ms，零依赖
- 为什么不用原计划的 Windows Shell API：实测（zh-CN Win10 22H2）`GetDetailsOf` 的媒体属性为空（时长/分辨率列拿不到值），且列序随语言环境变化、值是格式化字符串还要二次解析
- ffprobe 依旧不引（+50MB 原生二进制，违反硬约束）；解析失败回退缩略图尺寸占位，不阻塞导入

**已完成（2026-10-24）**

- `Asset.duration`（可选字段，秒）：`SCHEMA_VERSION` 仍为 1，老库不需要迁移
- 入库即提取；老库走「设置 → 修复资源」回填时长，并把缩略图占位尺寸换成真实分辨率
- 界面：卡片右下角时长角标（`0:05`）；详情「产物文件」显示真实分辨率与时长
- 卡片悬停预览（2026-10-27）：静音播放，按播放进度封顶 3 秒后停在当前帧；移出即恢复封面
- 黑白灰调柔随 0.7.0 一并发布（原计划 0.7.1）：暗色背景 `#0a0a0b → #131315`、亮色 `#ffffff → #f7f7f8`，窗口底色与标题栏同步
- 验收：`scripts/verify-video-meta.cjs` 全过（合成 MP4/WebM、真实样本、损坏文件安静降级、悬停预览、repair 回填）；typecheck / build / 全量 verify 回归通过

**剩余**

- 封面抽帧：系统缩略图质量可用，暂不做自选帧
- 验收基线不变：时长与分辨率与文件属性一致（误差 ≤ 1 秒，已达成）；不引入需要 node-gyp 的包（已达成）

### 5.2 0.7.1 卡片固定尺寸（2026-10-27 确认，已实现）

**问题**：左右栏收起/展开时卡片仍会一次性放大缩小——0.4.1 只解决了「动画期间的连续缩放」，卡片宽度仍按容器宽度均分，动画结束后重排会跳变一次。

**要做什么**

1. `Gallery` 的 `cardW` 改为固定值（跟随 `thumbSize`，120–380 由现有滑杆控制），不再按容器宽度均分
2. 左右栏收放、详情开关时只增减列数；`ResizeObserver` 等宽度稳定后再重排列数，但卡片宽高不变
3. 右侧允许留白，不拉伸卡片

**验收**

- 侧栏收起/展开、左右栏开关前后，同一张卡片的宽高像素完全不变（截图/断言）
- 列数变化正确（1440 宽下：侧栏展开 5 列 → 收起 6 列）
- 缩略图大小滑杆仍然生效；`verify-ui` / `verify-readability` 回归通过

**成本**：低。

**状态（2026-10-27）**：已完成。`cardW` 固定为 `thumbSize`，列数按可用宽度计算；`verify-ui` 新增断言，左右栏收放前后卡片宽度不变（误差 ≤ 0.5px）、列数只增不减。

### 5.3 0.8.0 模型词表（2026-10-27 确认，已实现）

**问题**：`params.model` 是自由文本，同一模型会出现「即梦3.0 / 即梦 3.0 / Jimeng 3.0」等写法，筛选、统计、批量操作全部对不齐。

**要做什么**

1. **数据模型**：`library.json` 新增 `models[]`（`{ id, name, kind: image|video|other, builtin? }`）；`entry.params.model` 保留字符串快照（分享包、单页 HTML、旁车文件仍是字符串，旧版可读）；`SCHEMA_VERSION` 不变，仅加可选字段
2. **内置预设词表**：首次建库/升级时种入常用模型（图像：MJ V6.1/V7、SDXL、Flux.1、即梦图片；视频：即梦 3.0、可灵 1.6、Runway Gen-3、Sora、Veo 3、海螺 02、PixVerse V4、Vidu Q1、Wan 2.1…）；`builtin` 标记，可「重置默认词表」；本地优先，不做云端同步
3. **录入改造**：编辑器模型字段 → 可搜索下拉（按 视频/图片/其他 分组、带使用数）；输入新名字显示「＋ 新建模型"xxx"」，回车即入词表；**不允许产生词表外的值**
4. **设置 → 模型管理**（复用标签管理骨架）：按使用数排序、重命名（可选同步历史条目）、合并疑似重复（归一化 + 编辑距离 ≤ 2 + 包含关系，沿用标签近似建议）、删除、重置默认词表
5. **侧栏「模型」筛选区**：词表驱动，点击筛选，可与类型/标签/搜索叠加

**验收**

- 同一模型在录入侧只允许「从词表选择」或「新建入库」两种途径，无法直接产生自由文本
- 重命名后：卡片、详情、筛选结果同步；历史条目按用户勾选同步或保留原文
- 老库散装模型可一键归并，归并后无孤儿引用
- 点模型 chip 立即过滤，与类型/标签/搜索叠加结果正确
- 分享包 / 单页 HTML 仍以字符串展示模型，旧版本可打开

**成本**：中。数据层小，主要在编辑器与设置面板的交互。

**与现有约束**：只加可选字段，不动 `SCHEMA_VERSION`；不引新依赖。

**状态（2026-10-27）**：已完成（0.8.0；0.8.1 补上分享包携带词表）。词表随库种入/回填，编辑器改为受控选择器，右栏新增「模型管理」（重命名可选同步历史、疑似重复合并、未入词表一键加入、恢复默认），侧栏新增模型筛选；`verify-models.cjs` 全过。入口与标签管理一致，放在右栏而不是设置弹窗（与现有信息架构统一）。

## 七、明确不做

写下来是为了以后不被反复讨论：

| 不做 | 原因 |
| --- | --- |
| 云端同步 / 账号体系 | 违背"本地优先、库自包含"。用户要同步就自己放网盘 |
| 内置 AI 生成 | 本工具管"已产出的资产"，不负责生成。接生成器只会变成另一个产品 |
| 团队协作 / 权限 | 个人工具。多人共享走"导出分享包"这条路够了 |
| 移动端 | 素材在电脑上产生，管理也在电脑上 |
| 用数据库替换 JSON | 见 `docs/架构与数据模型.md` 第三节：构建可靠性 > 极限性能 |
| 自动上传到图床 / 社交平台 | 同上，越界 |

## 八、技术债（与功能并行）

这些不产生新功能，但不还会越来越贵。按"什么时候必须还"排序：

| 债 | 触发条件 | 还法 | 现在要不要还 |
| --- | --- | --- | --- |
| 状态刷新是全量 IPC | 单库 > 2 万条 | 改增量补丁 | 不还，当前量级无感 |
| 重复检测 O(n²) | 单库 > 5 万张图 | 按 phash 前缀分桶预筛 | 不还 |
| 没有 E2E 测试 | 每次改动都要手动回归 | Playwright 驱动 `out/main` | 0.3.0 先扩现有断言脚本，不引新依赖 |
| 分享包全量导出 | 用户频繁导出大库 | 增量包（依赖归档格式版本升级） | 0.11.0 一起做 |
| 视频分辨率不准 | 0.7.0 做视频时 | 纯 JS 解析容器头（`video-meta.ts`），已实现并回填老库 | ✅ 已解决 |
| 单库只能开一个实例 | 需要同时开两个库 | 多实例锁 | 有意为之，不改 |

> 0.3.0 的标签合并与 AI 链路至少要有断言：可以新增 `scripts/verify-tags.cjs`，不要为了测试引入新框架。

## 九、怎么推进（每次发版的固定动作）

1. 从"当前站"按顺序取一项，确认验收标准没变
2. 开短分支 `feat/xxx`，完成后 squash 合并回 `main`
3. 一个提交只做一件事，提交信息遵循 Conventional Commits
4. 本地验证：`npm run typecheck` + `node scripts/demo-seed.mjs` + `verify-import` / `verify-pack` / `verify-tags` / `verify-ai` / `verify-keys` / `verify-ui` / `verify-video-meta` / `screenshot`
5. 更新 CHANGELOG 的 `[未发布]`
6. 按 `docs/发布规范.md` 升版本 → 改 CHANGELOG 标题 → 打注解标签 → push
7. 发布后回本文勾掉状态，把新发现的问题补进候选池

**本机特别注意**：本地 `npm run dist` 会被 `release/` 里的锁死文件挡住，打包一律走 CI。不要在本地反复试，也不要换输出目录绕过（见发布规范第 9 节）。
