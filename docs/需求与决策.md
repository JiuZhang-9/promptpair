## 2026-11-15 实用化方向（用户决策记录）

**背景**：0.11.0 后用户判断工具「还不太实用」——录入提示词和储存提示词的实际作用都不大。决定以「快速批量录入真实来源」为切入点，先把工具套用到真实模板里。用户收藏提示词多基于公众号文章或官方文档，需要把「一堆提示词」快速录入的能力；现阶段 UI 手动录入太慢，先走命令行通道。

**参考项目**：CLI-Anything（HKUDS 开源）——把有源码的软件自动转成 CLI 供 Agent 调用。promptpair 采用同一思路：主进程加 `--cli` 无头分支，复用 library.ts / media.ts 全部核心逻辑（sha256 去重、缩略图、dHash、schema 迁移）。

**核心框架（用户原话要点，不删减）**：

1. **明确核心定位**
   - 提示词是必须的；图文对照更好，但有时可能没有图
   - 只有图是不行的——锚定提示词为核心，显示图为附加功能；单纯收藏图片不是目的

2. **区分文生图与图生图**
   - 文生图（T2I）：没传图基本就是文生图提示词，最核心的区别
   - 图生图（I2I）：可细化为图像编辑

3. **处理特殊模型差异（Midjourney）**
   - MJ 有特殊的风格码和参数，与其他模型不同
   - MJ 8.2 有图像编辑能力，但「垫图」（Image Prompt，把图片作为底图去生图）是 MJ 与其他模型（如 SD）不同的特点；大部分模型通常只把传入图用于图像编辑

4. **功能模块分类**
   - 文生图（T2I）和图生图（I2I）的区别
   - 不同模型的管理
   - 参数管理：MJ 等特殊模型的特殊参数 + 绝大多数模型都有的固定参数（如图片比例、尺寸）
   - 风格差别：2D/3D、卡通/风格化、卡通/写实等
   - 长提示词和短提示词的区别：特别细化的内容往后放

5. **图片对比功能（用户标注：值得提前）**
   - 同提示词不同模型生成的图片，需要方便对比的方法
   - 图像编辑情况下，原图和编辑后图片的对照
   - 对比交互：左右滑杆、中间滑杆（支持左右、上下甚至斜着拖拽旋转）
   - 输出形式：输出成 GIF 图
   - 其他辅助：参考 ComfyUI 节点里的图片对照、图片压缩、图片复制、批量压缩、批量重命名、提示词绑定在图的元数据里

**实践第一步**：用户提供第三方工具「MJ码图对照_完整版」（`E:\Download\NetDiskDownload\7.最强角色-场景-巨兽资产生成\`），一次性工具但使用模式受用户喜欢。任务：把其中全部内容提取进 promptpair，作为 `--cli` 批量录入通道的首次实战。

## 2026-11-15 CLI 通道与首次实战（MJ码图对照导入）

**做了什么**
- 新增 `src/main/cli.ts`：`--cli` 无头模式（参照 CLI-Anything「同一个 exe 两种用法」的思路），复用 library.ts / media.ts 核心逻辑
- 命令：`list`（只读）/ `add --batch <json>`（写库），支持 `--dry-run` 预检、`--library` 指定库
- 写保护：写配置库前检查 PromptPair 是否在运行 + 单实例锁；写前自动备份 `library.backup-cli-<时间戳>.json`
- 只读 CLI 不参与单实例锁，可与 GUI 并存；写操作必须独占
- originId 幂等：同批重复执行 = 更新同一条不重复创建（实测二跑 0.8s / 801 媒体全复用）

**映射（用户确认）**
